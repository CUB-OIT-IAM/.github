# Contributing to CUB-OIT-IAM Repositories

Thank you for contributing! Please follow these organization-wide standards when submitting changes.

## Development Workflow
1. Create a feature or fix branch from `main` (e.g., `feat/short-description` or `fix/issue-123`).
2. Keep pull requests focused on a single concern.
3. Ensure all CI checks, linters, and automated security scans pass before requesting review.
4. Obtain at least two approval from a designated code owner.
5. Final Merge PR title should be follow Conventional Commit notation.

## Commit & Code Standards
- Write clear, descriptive commit messages.
- Never commit secrets, API keys, or credentials to any repository.
- Update relevant documentation and unit tests alongside code changes.
